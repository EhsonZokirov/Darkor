# DARKOR

Каталог блогеров Таджикистана: поиск, фильтры, профили авторов, заявки на рекламу и форма добавления блогера.


Стек: React 19, Vite, React Router, react-icons.

## Запуск

```bash
npm install
npm run dev      # режим разработки
npm run build    # сборка в папку dist
npm run preview  # просмотр собранного сайта
npm run lint     # проверка кода
```

## Что менять и где

| Что | Где |
| --- | --- |
| Название, e-mail, Instagram, адрес формы, категории | `src/config.js` |
| Ключи базы данных | `.env` (образец в `.env.example`) |
| Структура базы и права доступа | `supabase/schema.sql` |
| Список блогеров | `src/data/bloggers.js` |
| Фото блогеров | `src/images/` |
| Цвета, шрифты, анимации | `src/index.css` (переменные в начале файла) |

### Добавить блогера

В `src/data/bloggers.js` скопируйте любой объект, поставьте новый `id`, импортируйте фото из `src/images/` и заполните поля.
Поле `city` — это город блогера (например, «Душанбе»).

## Как работают формы

Формы «Добавить блогера», «Заказать рекламу» и «Контакты» проверяют поля и отправляют заявку одним из двух способов:

1. **Если в `src/config.js` указан `FORM_ENDPOINT`** (например, адрес на [Formspree](https://formspree.io)), заявка уходит туда POST-запросом в формате JSON.
2. **Если `FORM_ENDPOINT` пуст**, открывается письмо в почтовой программе пользователя с уже заполненным текстом (`mailto:`). Заявка также сохраняется в браузере пользователя.

Чтобы заявки приходили автоматически, без участия пользователя, создайте форму на Formspree и вставьте её адрес в `FORM_ENDPOINT`.

## Бэкенд (Supabase)

Без бэкенда сайт работает как витрина: каталог берётся из `src/data/bloggers.js`, а формы отправляют заявки письмом.
С подключённым [Supabase](https://supabase.com) (есть бесплатный тариф) появляется:

- регистрация и вход блогеров (почта и пароль), восстановление пароля;
- личный кабинет: блогер сам заполняет анкету, загружает фото и правит её;
- модерация: новая или изменённая анкета попадает в каталог только после одобрения администратором;
- админ-панель `/admin`: одобрить, отклонить, отредактировать или удалить анкету, читать заявки на рекламу и сообщения с сайта;
- заявки на рекламу и сообщения из формы «Контакты» сохраняются в базе.

Блогеры из `bloggers.js` продолжают показываться в каталоге вместе с блогерами из базы.

### Как подключить

1. Создайте проект на [supabase.com](https://supabase.com).
2. Откройте **SQL Editor**, вставьте весь файл `supabase/schema.sql` и нажмите **Run**. Он создаёт таблицы, права доступа и хранилище для фото. Файл можно запускать повторно.
3. Скопируйте `.env.example` в `.env` и впишите адрес проекта и ключ `anon` (**Project Settings → API**).
4. Выполните `npm install` и `npm run dev`.
5. Зарегистрируйтесь на сайте (кнопка «Войти»), затем в **SQL Editor** назначьте себя администратором:

   ```sql
   update public.profiles
      set role = 'admin'
    where id = (select id from auth.users where email = 'ваша@почта.com');
   ```

   После этого в меню появится пункт «Админ».

### Важно

- **Подтверждение почты.** По умолчанию Supabase просит подтвердить почту после регистрации. Для проверки можно отключить: **Authentication → Providers → Email → Confirm email**. Для настоящего сайта лучше оставить включённым.
- **Ключ `anon` публичный**, он попадает в браузер, и это нормально: данные защищены правилами доступа (Row Level Security) из `schema.sql`. А вот ключ `service_role` нельзя вставлять ни в `.env`, ни в код сайта.
- **Публикация на Netlify.** Добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в **Site settings → Environment variables** и пересоберите сайт.
- **Адреса для входа.** В Supabase в **Authentication → URL Configuration** укажите адрес вашего сайта, иначе ссылки из писем подтверждения будут вести не туда.

## Что настроить после обновления

Часть функций работает сразу, часть требует ваших аккаунтов. Ниже — что именно сделать.

### 1. Обновить базу (обязательно)

Откройте **Supabase → SQL Editor**, вставьте весь файл `supabase/schema.sql` и нажмите **Run**. Он безопасен для повторного запуска и добавляет защиту от потока заявок: больше 30 заявок или сообщений за 10 минут база не примет. Лимит меняется в функции `limit_submissions()`.

### 2. Письма (подтверждение почты и сброс пароля)

Встроенная почта Supabase рассчитана на тесты: очень мало писем в час и, как правило, только на адреса участников проекта. Для настоящего сайта подключите свою почту:

1. Заведите аккаунт в почтовом сервисе (например [Resend](https://resend.com), [Brevo](https://brevo.com) или Gmail с «паролем приложения») и получите SMTP-данные.
2. Supabase → **Authentication → SMTP Settings** → включите **Custom SMTP** и впишите хост, порт, логин, пароль и адрес отправителя.
3. Supabase → **Authentication → URL Configuration**: в **Site URL** укажите адрес сайта, а в **Redirect URLs** добавьте `https://ваш-сайт/**` (нужно для ссылки «Забыли пароль?»).

### 3. Бесплатный Supabase «засыпает»

Бесплатный проект ставится на паузу примерно после недели без обращений. Сайт при этом перестанет работать с базой. Решения: заходить на сайт и в панель Supabase хотя бы раз в неделю, поставить бесплатный пинг-сервис (например [UptimeRobot](https://uptimerobot.com), который раз в несколько минут открывает главную страницу) или перейти на платный тариф. Если проект всё-таки уснул, нажмите **Restore** в панели Supabase.

### 4. Telegram-уведомления о новых заявках

Код готов: `supabase/functions/notify-telegram/index.ts`.

1. В Telegram найдите **@BotFather**, команда `/newbot`, получите токен. Напишите своему боту любое сообщение.
2. Узнайте свой chat id (например, через бота **@userinfobot**).
3. Установите [Supabase CLI](https://supabase.com/docs/guides/cli) и выполните:
   ```bash
   supabase login
   supabase link --project-ref ВАШ-REF
   supabase secrets set TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... WEBHOOK_SECRET=длинная-случайная-строка
   supabase functions deploy notify-telegram --no-verify-jwt
   ```
4. Supabase → **Database → Webhooks → Create a new hook**: таблица `ad_requests`, событие **Insert**, тип **Supabase Edge Functions**, функция `notify-telegram`, в заголовки добавьте `x-webhook-secret` со значением из шага 3. Повторите для `messages` и `bloggers`.

### 5. Свой домен

1. Купите домен у регистратора.
2. Netlify → **Domain management → Add a domain** и следуйте подсказкам по DNS (HTTPS включится автоматически).
3. Обновите адреса: в Supabase (**Site URL** и **Redirect URLs**), в `index.html` (теги `og:url`, `og:image`, `twitter:image` содержат `https://darkormedia.netlify.app`) и в `VITE_PLAUSIBLE_DOMAIN`, если используете счётчик.

### 6. Счётчик посещений

Подключите [Plausible](https://plausible.io) (платный) или [Umami](https://umami.is) (есть бесплатный тариф): добавьте переменную `VITE_PLAUSIBLE_DOMAIN` или `VITE_UMAMI_ID` в `.env` и в **Netlify → Environment variables**, затем пересоберите сайт. Без переменных счётчик не подключается. Политика конфиденциальности уже упоминает обезличенную статистику.

### 7. Уведомления админа: «прочитано» и цифра в меню

В меню у админа рядом со словом «Админ» горит красная цифра: сколько новых заявок и сообщений
не прочитано плюс сколько блогеров ждут проверки. На телефоне — красная точка на кнопке меню.
В админке есть кнопки «Прочитано», «Прочитать все» и «Вернуть в новые» — ничего не удаляется.

Чтобы это заработало, **один раз** откройте Supabase → SQL Editor, вставьте содержимое файла
`supabase/admin_read_status.sql` и нажмите Run (повторный запуск безопасен).
Пока файл не запущен, админка работает как раньше и показывает подсказку.

### 8. Языки и тексты

- Сайт на русском и таджикском, переключатель РУ / ТҶ в меню. Переводы лежат в `src/i18n/tg.js` (ключ — русский текст), политика — в `src/content/privacy.js`. Если фразы нет в словаре, показывается русская.
- Таджикские тексты подготовлены без носителя языка: **покажите их таджикоязычному человеку** перед запуском.
- Политика конфиденциальности — шаблон для информирования пользователей, а не юридическая консультация. Проверьте её на соответствие законам вашей страны.
- Данные блогеров из базы (имена, описания, теги) не переводятся: это то, что ввёл сам блогер.

### 9. Пароль базы и история Git

Если в репозиторий когда-либо попадал пароль базы данных (в README была строка, похожая на пароль), удаление строки не убирает её из истории Git. Смените пароль: Supabase → **Project Settings → Database → Reset database password**. Сайту этот пароль не нужен, он использует только публичный ключ.

## Публикация

Сайт — одностраничное приложение. Файл `public/_redirects` уже настроен для Netlify, чтобы прямые ссылки (например, `/blogger/3`) открывались корректно. На другом хостинге включите перенаправление всех адресов на `index.html`.

## Мини-игра DAVODAVSHIK (`/game`)

Бесконечный раннер на HTML5 Canvas: 5 блогеров на выбор, двойной прыжок, бонусы, скины, звук, рекорды.
Код игры лежит отдельным модулем в `src/game/` (движок, отрисовка, персонажи, звук, рекорды, интерфейс), страница — `src/pages/Game.jsx`.

- **Рейтинг в Supabase:** один раз выполните `supabase/game.sql` в SQL Editor (или весь `schema.sql`). Таблицы закрыты, результат пишется только через функции `start_game_run` / `finish_game_run`: сервер сам считает время забега и отклоняет невозможные очки. Без этого файла игра работает, рекорды хранятся в браузере.
- **Лица блогеров:** лежат в `public/game/faces/<id>.jpg` (`abduvali`, `shabnam`, `magachill`, `ehsonsho`, `suleyman`), квадрат 256×256. Чтобы заменить лицо, подмените файл. У каждого блогера своя одежда в скине «Классика» (`outfit` в `src/game/characters.js`).
- Скины открываются по числу собранных бонусов (`src/game/characters.js`).
